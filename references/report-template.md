# Report Template

Use this compact Bankr-friendly shape:

```text
Verdict: <Pass | Watch | Small Spec | Trade Candidate>
Headline: <optional blunt frame>
Confidence: <Low | Medium | High>

What it is:
<1-2 lines on what the project is claiming to be>

Best finding:
- <single strongest verified contradiction or validation>

Evidence:
- <verified point>
- <verified point>
- <verified point>

Sources:
- Website/docs: <literal URL(s) or blocker>
- X/social: <literal handle/URL or blocker>
- GitHub/code: <literal GitHub URL or blocker>
- Source trace: <compact checked-route list>

Token / launch:
- <only include when a live token or launcher materially matters>

My read:
<2-4 sentences; classify what it really is and the practical posture>

Would change my mind:
- <specific missing proof>

Unknowns:
- <1-3 material blockers>
```

If there is no headline, omit the `Headline:` line and place `Confidence:` second.

If token/launcher detail does not materially affect the verdict, omit `Token / launch:` entirely rather than padding it with blanks.

Good positive headline patterns:

- `LIVE PLUMBING`
- `REAL PRODUCT / LEGIT BUT EARLY`
- `REAL PRODUCT, WEAK TOKEN`

If a product flow appears real but you did not personally execute the final onchain action, say that plainly in `Evidence` or `My read`:

- `I did not connect/sign, so I did not independently confirm a completed buy or redemption.`
